* manage tests and evaluations
* analyze academic performance

* support multi-branch institutes
* support future AI systems
* support future plugins
* scale without architectural rewrites

# 5. DEVELOPMENT GOVERNANCE RULES

## Rule 1

Frontend NEVER owns authentication logic.

---

## Rule 2

Frontend NEVER validates permissions.

Backend ALWAYS validates:

* authentication
* authorization
* RBAC

---

## Rule 3

No direct DB access from API routes.

Correct flow:

```text id="jlwm41"
Route
 ↓
Service
 ↓
Repository
 ↓
Database
```

---

## Rule 4

Every module must contain:

* api
* service
* repository
* models
* schemas
* validators
* permissions
* tests

---

## Rule 5

All features MUST generate events.

---

## Rule 6

All DB schema changes require migrations.

---

## Rule 7

No hard deletes.

Use:

```text id="jlwm42"
is_deleted = true
```

---

## Rule 8

Plugins NEVER directly access core DB.

Plugins interact ONLY via:

* APIs
* Events

---

## Rule 9

Claude Code implements predefined standards ONLY.

Claude NEVER invents:

* architecture
* naming conventions
* DB patterns
* auth flow
