The platform is being designed as a:

# “Modular Academic Operating System”

The system must:

* track attendance

# 5. DEVELOPMENT GOVERNANCE RULES

These rules are MANDATORY for Claude Code development.

---

# Rule 1

Frontend must NEVER own authentication logic.

---

# Rule 2

Frontend must NEVER validate permissions.

Backend ALWAYS validates:

* authentication
* authorization
* RBAC

---

# Rule 3

Claude Code must NEVER directly access DB from API routes.

Correct flow:

```text id="wnjkqk"
Route
 ↓
Service
 ↓
Repository
 ↓
Database
```

---

# Rule 4

Every module must contain:

* API layer
* service layer
* repository layer
* schemas
* validators
* tests

---

# Rule 5

Every feature must generate events.

---

# Rule 6

Every module must have automated tests.

---

# Rule 7

No hard deletes allowed.

Use:

```text id="dl2vy2"
is_deleted = true
```

---

# Rule 8

All DB schema changes require migrations.

---

# Rule 9

Future plugins must use:

* APIs
* Events

Plugins must NEVER directly manipulate core DB.

# 8. AUTHENTICATION ARCHITECTURE

# Standard Production Authentication

---

# Recommended Flow

```text id="abqs5v"

      ↓
Backend Auth Validation
      ↓
JWT Access Token Generated
      ↓
Refresh Token Generated
      ↓
Stored in HTTP-only secure cookies
```

---

# Security Rules

Frontend MUST NOT:

* store refresh tokens
* validate permissions
* control RBAC

Backend ALWAYS controls:

* auth
* RBAC
* access control

| Token         | Duration |
| ------------- | -------- |
| Access Token  | 15 mins  |
